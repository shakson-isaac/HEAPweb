# Decommissioned prototypes

Python scripts that were the *first* implementation of something now generated
elsewhere. They are kept, not deleted, and they do not run by default.

## The rule

**One artifact, one generator of record — in the language that owns the repo.**

- `HEAP` and `HEAP_manuscript` are R. Anything the manuscript reads is generated
  by R, in HEAP, and written to `$HEAP_OUTPUT`.
- `HEAPweb` is Python. Anything the website reads is generated by Python, in
  HEAPweb, and written to `build/derived`.

A prototype crossing that line (Python producing a manuscript table) is fine as
a way to work out the shape of a thing quickly. It is not fine as the thing that
keeps producing it. Once ported, the prototype is **decommissioned**:

1. moved here, out of `tools/`, so it is not in the working set;
2. banner at the top naming the generator of record;
3. a `--cross-check` guard, so a bare `python3 build_*.py` exits instead of
   writing a file that looks shippable;
4. any output it already left in `build/derived` moved to
   `build/derived/_decommissioned/`, so it cannot be wired into
   `tools/web_sections.tsv` by someone who finds the filename.

## Why keep them at all

They are cross-check oracles. Diffing the R port against
`build_supp_triad_wide.py` is what caught the `PEtrans` bug, where protein→exposure
edge endpoints were written as disease→exposure: the output had correct
dimensions and plausible values, and 9,656 tier lookups were silently wrong. A
second independent implementation is the only thing that finds that class of
error. Run one with `--cross-check` after changing the R generator.
